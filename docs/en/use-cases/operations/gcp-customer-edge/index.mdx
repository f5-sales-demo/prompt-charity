## Before you begin

Use an existing authorized test GCP project and F5 Distributed Cloud tenant with permission to create and delete a site. You need GCP CLI authentication and separate Terraform Application Default Credentials, sufficient N2 quota, and Terraform 1.5 or newer. Your agent discovers the host and chooses appropriate native commands.

**Using a GCP service account:** select impersonation in the prompt's GCP authentication input and supply the full
service-account email and owning project. The single prompt returns five IAM gates with evidence, owners and next actions, plus a private request for your IAM
team when access is blocked. It pauses for administrator confirmation, rechecks access for at most ten minutes and
keeps IAM administration, approved local authentication setup and CE deployment as separate approvals. A private
checkpoint supports resume after setup approval; planning creates no workspace files.
Impersonation needs Token Creator on the service account and separate deployment permissions in the target project.
Administrator IAM/API changes are prerequisites, outside the CE deployment. Keep credentials out of chat.

**Private provider access comes first:** obtain an invitation to
[F5Networks/terraform-provider-f5xc-preview](https://github.com/F5Networks/terraform-provider-f5xc-preview) and
authenticate to its releases. An inaccessible private repository may return a misleading 404. The prompt resolves the
newest non-draft release on every fresh run, including prereleases, and rejects unsupported platform assets. It uses no
fixed release default. After discovery and review, the saved deployment plan binds the selected exact version and
checksum so they cannot change between plan and apply. Existing deployments require a reviewed upgrade plan.

## Expected architecture

One `n2-standard-8` instance has separate SLO (outside) and SLI (inside) VPCs/subnets. SLO Cloud NAT supplies outbound access; the VM has no public IP. Secure Mesh Site v2 uses JWT registration. NIC order is explicit: `ens4 → SLO`, `ens5 → SLI`. The default saved Terraform plan creates 15 resources, or 16 with optional SSH.
The boot disk defaults to 120 GB `pd-balanced`, reserving 50% above F5's 80 GB Mesh minimum for software, logs and upgrades.
Planning increases this for newer requirements and checks quota/cost. Guest-usable space is verified separately from
the GCP disk's provisioned size.

Supply your project, region/zone, unique short name prefix, two independently checked non-overlapping private `/26`
ranges, authorized tenant API URL and private credential source. SSH defaults to none. Credentials must stay outside
chat, published configuration and the Terraform input directory. State, saved plans and VM metadata must remain private.

## Timing and completion

Allow roughly 30-50 minutes, usually 20-45 minutes for registration and upgrades. Cold downloads may take longer. The agent polls every 30 seconds with visible elapsed time and keeps the session active. After 60 minutes it preserves evidence and performs bounded diagnostics; a timeout or invalid response cannot pass.

Completion requires consecutive validated `ONLINE` observations at least 30 seconds apart, verified `ens4 → SLO`
and `ens5 → SLI` roles, and a post-registration `terraform plan -detailed-exitcode` returning zero. Recheck `ONLINE`
after that plan; a regression resumes the original bounded polling. Regional Edge connectivity is recorded separately.
Do not accept a pending status or an earlier clean plan as completion.

## Teardown and fallback

When teardown is authorized, inspect and apply a saved destroy plan, then independently prove the owned GCP resources and XC site are absent. This includes the temporary marketplace licence probe. Keep private evidence until cleanup is verified.

Use the [step-by-step fallback guide](/prompt-charity/en/use-cases/operations/gcp-customer-edge/fallback/) if your agent cannot execute the workflow. It contains the nine grouped Terraform files and the same acceptance boundaries.
