## Before you begin

Plan one dual-interface F5 Distributed Cloud Customer Edge (CE) in an authorized Google Cloud Platform (GCP) test project. Allow roughly 30–50 minutes; registration and upgrades usually take 20–45 minutes, and cold downloads can take longer.

- **Access and tools:** tenant permission to create and delete a site, GCP command-line authentication, separate
  Terraform Application Default Credentials, sufficient N2 and storage quota, and Terraform 1.5 or newer. For
  impersonation, supply the service-account email and owning project; Token Creator and target-project deployment
  permissions are separate prerequisites.
- **Private provider:** obtain an invitation to [F5Networks/terraform-provider-f5xc-
  preview](https://github.com/F5Networks/terraform-provider-f5xc-preview) and authenticate release access. A private-
  repository 404 can mean missing access. Each fresh run discovers the newest non-draft release, including prereleases,
  checks platform support, and binds its exact version and checksum to the saved plan. Existing deployments need a
  reviewed upgrade plan.
- **Inputs:** project, region/zone, unique short prefix, two checked non-overlapping private `/26` ranges, tenant API URL and private credential source. SSH defaults to none. Keep credentials outside chat and Terraform inputs; state, saved plans, metadata and raw evidence remain private.

The default architecture uses one `n2-standard-8` VM without a public IP, separate outside (SLO) and inside (SLI)
networks, SLO Cloud NAT, and Secure Mesh Site v2 JWT registration. NIC order is `ens4 → SLO`, `ens5 → SLI`. The 120 GB `pd-balanced` boot disk reserves 50% above F5's 80 GB
Mesh minimum; planning checks current requirements, image size, quota and cost. Verify guest-usable space separately.
Omit Shielded VM configuration for non-UEFI images; review token-dependent metadata before apply and verify live values
privately afterward.

## Verify and clean up

The agent polls every 30 seconds with visible elapsed time and keeps the session active. The 60-minute registration deadline remains anchored to VM creation across resumes. Timeout, invalid responses and pending states cannot pass; preserve evidence for bounded read-only diagnostics.

Completion requires:

- Consecutive validated `ONLINE` observations at least 30 seconds apart.
- Verified `ens4 → SLO` primary and `ens5 → SLI` nonprimary interface roles.
- A post-registration `terraform plan -detailed-exitcode` returning zero, followed by another `ONLINE` check. A regression resumes the original bounded polling and requires fresh interface and plan evidence. Record Regional Edge connectivity separately.

When teardown is authorized, inspect and apply a saved destroy plan, then independently prove all owned GCP resources, the temporary marketplace licence probe and both XC site representations are absent. Preserve private evidence until cleanup is verified. Recovery mutations require a reviewed plan.
